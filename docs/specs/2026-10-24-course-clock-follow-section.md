# Spec：教务课程随学校作息更新，统一课表、详情、提醒与小组件

> 状态：已实施并完成双轴评审，修复 1 轮；详见[实施与评审报告](../2026-10-24-course-clock-follow-section-implementation-review.md)。本文取代旧规格中“教务导入时保存节次钟点快照，之后继续优先使用”的规则。

> GitHub：[Issue #7](https://github.com/jiangkaiqi2005/Recess/issues/7)，标签 `ready-for-agent`。

## Problem Statement

学生从教务系统导入课表，并在设置中填写学校的节次作息后，同一门课仍会显示两套时间。例如，周日“计算机网络”安排在第 6–9 节，当前学校作息对应 14:25–18:05，周视图中的课程也占据这四节；但点开详情或查看桌面小组件，却显示 14:55–19:45。

这组错误钟点来自 App 的内置作息：教务导入将当时本地节次表推算出的钟点保存到了课程中，后续修改学校作息时，课程详情、今日课程、提醒和小组件仍优先读取这份旧快照。刷新小组件也会重新生成相同的错误钟点。

学生的默认前提是教务给出的课程安排正确。App 应按教务提供的星期、节次、周次和已经设置好的学校作息显示课程，不应要求学生理解快照、修复旧数据、确认时间来源或重新导入。

## Solution

教务课程默认跟随当前学校作息。导入只保存教务实际给出的课程安排，不把 App 推算的钟点当作教务提供的独立时间。修改节次作息后，课程详情、今日课程、课前提醒和桌面小组件统一使用更新后的结果。

已有课程默认按节次作息解释，升级后自动生效。保留原始课程数据，不增加修复入口、迁移确认框、备份步骤或撤销功能。用户已经确认本次出现问题的当前学期全部来自教务导入。

真正带有独立钟点的新 ICS／JSON 课程继续使用文件给出的时间。课程应能明确表达“跟随节次作息”与“使用独立钟点”，不能再通过“是否存着一段钟点字符串”区分两者。

## User Stories

1. 作为学生，我希望教务提供的星期、节次和周次被原样使用，以便导入结果符合学校的安排。
2. 作为学生，我希望 App 不把自己的默认钟点当成学校提供的时间，以便不会误以为学校安排发生变化。
3. 作为学生，我希望教务课程使用已经设置好的学校作息，以便第 6–9 节能显示为正确的 14:25–18:05。
4. 作为学生，我希望从周视图打开详情时看到相同的上课时间，以便不用在两个结果中猜测。
5. 作为学生，我希望从搜索或今日课程打开同一门课时得到相同的时间，以便入口不会改变结果。
6. 作为学生，我希望桌面小组件与课程详情一致，以便在桌面上也能确认上课和下课时间。
7. 作为学生，我希望课前提醒依据正确的开始时间安排，以便不会因为旧作息而迟到。
8. 作为学生，我希望今日课程的未开始、进行中和已结束状态按正确钟点计算，以便状态与实际安排一致。
9. 作为学生，我希望单独修改某节的开始时间后，相关教务课程随之更新，以便只维护一份学校作息。
10. 作为学生，我希望修改某节时长后，相关课程的结束时间也更新，以便下课时间保持准确。
11. 作为学生，我希望顺延作息、应用模板或恢复默认后，各入口继续使用同一规则，以便不同设置方式不会产生两套时间。
12. 作为学生，我希望已有教务课程在升级后默认使用当前作息，以便不用重新导入或逐门编辑。
13. 作为学生，我希望这次修正不增加额外提示或操作，以便照常打开课表就能使用。
14. 作为学生，我希望课程标识、名称、教师、教室、周次、颜色、备注和课程平台保留，以便修正时间不会丢失已整理的信息。
15. 作为学生，我希望重启应用后课程仍跟随作息，以便修正不会只在当前页面临时有效。
16. 作为学生，我希望编辑或复制教务课程后仍跟随作息，以便旧快照不会重新生效。
17. 作为学生，我希望新导入的 ICS 课程保留文件明确提供的钟点，以便日历中的真实安排被尊重。
18. 作为学生，我希望新导入的 JSON 课程保留文件明确提供的钟点，以便导入结果符合文件内容。
19. 作为学生，我希望没有提供独立钟点的文件课程也使用节次作息，以便不必重复填写可推算的信息。
20. 作为学生，我希望只有一个端点具有独立钟点时，另一端继续使用节次作息，以便不丢失已有的有效信息。
21. 作为学生，我希望导出并恢复新备份后保留课程的钟点使用方式，以便跟随作息的课程不会恢复成固定时间。
22. 作为学生，我希望恢复旧备份时旧教务快照不会重新主导显示，以便备份恢复不会带回这次问题。
23. 作为学生，我希望缺少可用作息时仍能看到课程节次，以便课程不会被隐藏或编造时间。
24. 作为维护者，我希望各入口共用同一课程钟点 module，以便一处规则调整能覆盖全部显示和提醒。
25. 作为维护者，我希望测试覆盖真实导入、设置和最终显示，以便发现“时间轴正确、详情和小组件错误”的完整问题。

## Implementation Decisions

- **权威输入**：教务抓取提供的星期、起止节次和周次是课程安排的依据；具体钟点使用用户已配置的节次作息。本次不增加从学校页面或接口自动抓取节次作息的能力，也不宣称当前抓取已取得学校真实钟点。
- **明确钟点使用方式**：课程持久化表示须区分“跟随节次作息”和“使用独立钟点”。前者始终按当前节次作息求值，即使历史数据中还保留钟点字符串也不使用；后者沿用逐端显式值优先、仅 null 端回退节次作息的规则。只增加表达这一区别所需的最小数据，不增加学校、导入批次或通用来源追踪系统。
- **已有数据的默认值**：缺少钟点使用方式的旧课程默认跟随节次作息，自动生效，不弹窗、不增加修复入口、不要求重新导入。原始钟点可以保留，但不能继续覆盖当前作息；不得通过匹配默认时间、颜色、课程名或 UUID 猜测来源。
- **兼容边界**：旧库没有记录导入来源，无法自动区分历史教务快照与历史 ICS／JSON 独立钟点。上述默认值统一适用于没有明确使用方式的旧记录；不承诺这类旧文件课程继续沿用历史独立钟点。保留原始钟点数据，不能把默认解释方式写成“已可靠识别旧教务来源”。新文件课程的独立钟点通过明确的使用方式保留。
- **新教务导入**：导入提交建立跟随节次作息的课程，不再把本地节次表推算出的钟点写成独立钟点。保留勾选、目标学期、合并／替换、自动配色、课程平台及整次提交原子性的现有行为。
- **新文件导入**：普通 ICS／JSON 明确提供至少一个独立钟点时，保留现有显式端点语义；没有独立钟点时跟随节次作息。不因这次修复重新映射文件课程的节次，也不扩大字符串清理或时间合法性规则。
- **编辑与复制**：保留原课程的钟点使用方式。修改跟随作息课程的节次后，钟点按新节次计算；不能因为复制、普通保存或旧字段仍有值而恢复快照优先。新建的普通节次课程默认跟随作息。
- **统一求值**：详情、今日课程、提醒和小组件继续通过现有课程钟点 module 求值。周视图保持按星期和节次排列，左轴继续展示全局节次作息；不在各入口复制选择规则。
- **刷新机制**：复用现有数据库课程流与应用级监听，在课程、节次作息或当前学期变化后刷新小组件并重排提醒。不新增后台抓取、分钟轮询或另一套原生课表规则。升级后的钟点使用方式必须在依赖它的数据首次对外使用前可用，不能先写出旧提醒或旧小组件数据再等待用户操作修复。
- **持久化与兼容**：数据库、领域表示和映射同步表达钟点使用方式；升级过程保留原有课程标识、业务字段、学期及平台关联，并支持旧版本数据库升级。具体迁移版本由实施时根据实际基线确定，不手改生成代码。
- **备份与恢复**：新备份携带钟点使用方式，恢复后逐门保留该语义；旧版 Recess 备份缺少此信息时使用与旧数据库相同的默认值。旧备份经“从备份恢复”或被文件导入识别为 Recess 备份时，不得把历史快照重新误认成新文件明确给出的独立钟点。普通外部 JSON 的显式钟点继续按普通文件导入规则处理。兼容既有有效备份，不静默丢弃无法理解的新语义。
- **缺失与无效输入**：延续现有节次降级和显式端点解析行为；缺少开始钟点时不生成臆造提醒，小组件拿不到完整范围时显示节次。独立钟点模式中的空字符串或不可解析值不因为本次调整被擅自当作 null。
- **界面范围**：不新增时间模式选择器、课程卡片钟点标识、修复按钮、备份提示或迁移确认。真正独立钟点课程与周视图全局时间轴可能不同，这是保留独立钟点后的既有例外，本次不重做时间轴布局。

## Testing Decisions

- 以现有公开流程为验收入口，断言最终课程显示、今日状态、提醒触发时刻、实际小组件 payload 和真实持久化结果，不断言私有解析函数、拆分方式或调用次数。
- 首要回归样例使用真实教务提交流程：周日第 6–9 节、周次 7／9／11／13，导入后将学校作息设置成第 6 节 14:25、第 9 节 17:20 且各 45 分钟，详情与小组件必须为 14:25–18:05，不能为 14:55–19:45。
- 复用现有课程钟点流程测试的真实内存数据库、ProviderContainer、课表页面以及周视图／今日课程／搜索点击入口；将原先要求“教务快照保持原值”的断言改为跟随作息，并保留真正独立钟点的对照课程。
- 复用现有设置到课表的流程测试，穿过单节编辑、顺延、模板和恢复默认入口，返回课表后实际点击详情。覆盖设置在导入前改变和导入后改变两种顺序。
- 复用现有小组件 MethodChannel adapter 捕获实际课次数据，注入固定日期和时间；在相同数据下检查起止钟点与日期。再次主动生成小组件数据不能恢复旧钟点。已有 payload 测试不等于 Android 桌面自动刷新已经验收。
- 使用现有提醒计算和通知平台 adapter 验证真实开始端、提前量、旧提醒重排与缺失开始钟点降级；今日课程测试验证更新后的时间边界。
- 升级测试从含旧快照的真实旧版数据库打开：读取课程及其钟点使用方式，随后穿过详情、提醒和小组件入口。验证自动跟随、无用户修复步骤、重启后仍有效，以及所有非钟点业务字段和平台关联保持一致。
- 对旧记录的默认值使用明确断言，不伪造历史来源；加入旧 ICS／JSON 风格记录，验证其原始钟点未被删除，但缺少明确使用方式时默认跟随节次的兼容策略。
- 新文件对照覆盖 ICS、普通 JSON、无独立钟点、只有开始端、只有结束端、完整独立范围，以及既有显式空字符串／不可解析值。修改学校作息后，真正明确的独立端点保持不变。
- 编辑、复制、保存及重新加载应保留课程钟点使用方式；更改跟随作息课程的节次后，最终显示使用新节次。
- 复用真实备份往返测试覆盖新语义、旧版 Recess 备份、普通外部 JSON、恢复和文件导入两条既有入口，避免通过备份重新引入快照优先。校验失败必须在覆盖前拒绝，失败保留原有数据。
- 保留既有周视图布局、分页、纵向滚动和无障碍回归。本次不为文档编写执行代码测试；实施时按仓库要求完成生成代码、严格静态分析和全套 Flutter 测试。
- Android 真机上的升级、桌面刷新及通知重排须单独验收；自动化通过不能替代真机结果，也不能宣称已读取过本次用户手机数据库。

## Out of Scope

- 从学校页面或接口自动提取节次作息，增加学校、接口或抓取来源。
- 让学生选择时间模式、手动识别旧课程来源，或新增修复入口、确认、自动备份和撤销功能。
- 根据钟点相等或其他启发式猜测历史导入来源，承诺无来源记录的旧文件课程保持原独立钟点行为。
- 修改教务给出的星期、节次、周次，重映射文件课程节次或自动去重。
- 重做周视图为绝对时间布局，给独立钟点课程增加卡片标识，改变当前周或学期计算规则。
- 通用来源追踪、后台重新抓取课表、精确闹钟和小组件样式调整。
- 本次规格编写阶段的代码实施、手机数据修改、构建发布、提交或推送。

## Further Notes

- 用户已确认当前学期全部来自教务导入，并明确要求默认正确，不增加旧数据修复提示。沿用用户已经设好的学校作息是此前确认的前提，不再另行访谈。
- 当前抓取合约与重庆大学适配器只提供课程安排，没有学校作息的读取证据；这不等于学校页面或接口没有作息。本次不登录学校核实或猜测接口字段。
- 旧持久化模型没有来源、学校、导入批次等标记。自动默认与“精确识别历史来源”是不同承诺；本文选择前者，保留原始数据，并明确旧独立钟点的兼容边界。
- 本文取代[课程钟点旧规格](2026-10-22-course-clock.md)中保留教务快照、禁止旧数据语义调整及相应测试要求；取代[导入提交旧规格](2026-10-22-import-commit.md)中教务节次钟点补全的要求。其他导入原子性、平台归属和独立端点规则继续有效。
- 遵守课程平台按学期与课程名归属的既有决策，以及由 Dart 预先计算课次、原生端只负责挑选与显示的小组件决策。
- 诊断阶段已在当前代码复现“默认作息导入 → 修改作息 → 点击详情／重新生成小组件”两处错误；未直接读取手机数据库，未实施修复。
