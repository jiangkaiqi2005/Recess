# Spec：学期变更完整提交，并维护可用的激活学期

> 状态：本地草稿，尚未实施；不发布 GitHub。

## Problem Statement

学生删除一个学期时，课程、课程平台和学期分多步独立删除。中间失败会留下“课程已删、学期仍在”的状态。页面还重复删除课程，并负责刷新多个 Provider；同一变更的完成条件分散在表单、页面和仓库中。

新建并激活学期也分成两次独立写入。应用启动完成默认学期播种后，如果在同一进程删除最后一个学期，后续读取不会再播种，可能得不到激活学期，与已有默认学期承诺不符。

## Solution

沿已有学期变更 seam 深化 module，把关联数据清理、创建或保存并激活、默认学期保持以及必要的状态刷新集中起来。学生完成一次学期操作时，所有相关数据一起成功或一起回滚。

页面调用既有应用入口后即可获得完整结果，不再掌握清理三个仓库及缓存失效的顺序。这个 interface 的 depth 为多个学期操作入口提供 leverage，并把一致性与验收的 locality 集中在学期变更规则。

## User Stories

1. 作为学生，我希望删除学期时同时删除它的课程，以便不留下无归属的课程。
2. 作为学生，我希望删除学期时同时删除它的课程平台，以便不保留无用的平台数据。
3. 作为学生，我希望关联清理失败时整个学期保持删除前状态，以便继续使用原课表。
4. 作为学生，我希望删除一个学期不影响其他学期的课程，以便保留其他学习安排。
5. 作为学生，我希望其他学期的同名课程平台保持原样，以便共享规则只作用于所属学期。
6. 作为学生，我希望创建并激活学期全部成功后再进入新学期，以便不会出现半完成的新建结果。
7. 作为学生，我希望创建并激活失败时原激活学期仍可用，以便继续查看原课表。
8. 作为学生，我希望删除非激活学期不会改变当前激活学期，以便不中断正在查看的课表。
9. 作为学生，我希望删除激活学期后按既有规则选择剩余学期，以便继续查看课程。
10. 作为学生，我希望删除最后一个学期后仍能得到已有承诺中的默认学期，以便应用继续保持可用。
11. 作为学生，我希望同一进程内删除最后学期后的行为与首次启动一致，以便不必重启解决空状态。
12. 作为学生，我希望保存、激活或删除成功后学期列表立即反映结果，以便确认操作完成。
13. 作为学生，我希望课表与激活学期同步，以便不会显示另一个学期的旧内容。
14. 作为学生，我希望保存当前周的操作也沿一致的状态刷新入口完成，以便返回课表时看到已保存设置。
15. 作为学生，我希望失败操作不会报告成功，以便决定重试还是保留当前状态。
16. 作为维护者，我希望通过学期公开操作和真实数据库验证一致性，以便无需依赖页面的隐藏调用顺序。

## Implementation Decisions

- 优先深化现有学期持久化与应用入口，删除页面中的重复关联清理，不以新增通用 CRUD module 代替真实规则集中。
- 学期、其课程及其课程平台的删除处于同一数据库事务；任一步失败均回滚全部清理。
- “保存并激活”作为一次完整提交，保存失败或激活失败均不保留半完成结果，并维持原激活状态。
- 保留已有激活选择规则：仍有学期而无激活项时，使用既有第一个学期策略；删除非激活学期时保持原激活项。
- 兑现既有默认学期规则：没有任何学期时生成一个默认激活学期，开学日为最近周一，总周数为 18。一次成功播种不能使后续空数据库检查永久失效。
- 保持默认学期创建的幂等和并发串行能力；不能因为去除永久缓存而在并发读取时生成多个默认学期。
- 完成一次变更后，由其应用入口集中处理必要的现有 Provider 失效；页面不再维护多项刷新清单。
- 沿用现有应用级监听刷新提醒和小组件，不让各学期页面分别执行派生更新，也不把数据库订阅改造作为前置条件。
- 课程平台遵守 ADR-0001；课程名相同但学期不同的数据严格隔离。
- 不改变手动当前周与查看周的含义；越界手动当前周按独立的《学期当前周有效性》Spec 调整到最近合法周，本 Spec 只集中完整提交与状态刷新。
- 无须 schema 迁移、通用仓储抽象或全局事件总线。

## Testing Decisions

- 用户已确认沿用现有公开 interface 和高位 seam 验收。断言数据库最终内容、激活状态及可见页面结果，不断言仓库调用次数或私有实现。
- 延续现有学期表单测试：真实内存数据库 adapter、两个学期、同名课程平台与目标学期课程。
- 通过数据库触发器令课程平台删除失败，断言课程、平台、学期及原激活状态全部保留；另覆盖最终学期删除失败。
- 对“保存并激活”注入激活写入失败，断言新建数据或原编辑数据及激活状态整体回滚。
- 覆盖删除非激活学期、删除激活学期但仍有其他学期、同一进程播种后删除最后学期以及随后多次读取。
- 覆盖并发默认学期读取，断言只存在一个默认学期，并验证默认开学日和周数的既有规则。
- 在现有 Provider 和学期/课表页面 seam 验证成功后可见状态一致，无需依靠关闭页面或重启；保留当前周与查看周的区别。
- 保留现有课程编辑事务和课程平台改名迁移回归，防止把相关删除范围扩大到其他学期。
- 实施后运行严格静态分析和全套 Flutter 测试。

## Out of Scope

- 改变默认学期的产品设计，允许新的长期空学期模式或引入回收站。
- 新增学期排序策略、跨学期移动课程、级联删除数据库迁移或通用数据一致性框架。
- 重复实现《学期当前周有效性》Spec 已确定的手动当前周调整规则，或重构周视图分页。
- 重做已有课程保存事务、课程平台归属或节次设置持久化队列。
- 把备份恢复完整提交绑定为本 Spec 的前置依赖。
