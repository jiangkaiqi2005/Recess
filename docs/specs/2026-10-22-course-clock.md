# Spec：集中课程钟点读取规则，统一详情、今日、提醒与小组件

> 状态：本地草稿，尚未实施；不发布 GitHub。

## Problem Statement

同一课程可以在今日课程里显示一个钟点，点进详情后却显示另一个钟点。例如课程自带 08:30–09:00，所处节次的全局时间为 08:00–09:40，今日课程优先使用前者，详情只读取后者。

提醒另行选择并解析开始钟点，小组件仅在课程自带完整起止钟点时显示范围。钟点来源规则分散，维护者必须同时检查多个入口，才能判断一次调整是否保持一致。

## Solution

让详情、今日课程、课前提醒和桌面小组件通过同一个课程钟点 module 读取钟点来源。每一端的课程显式值优先，只有该端为 null 时才回退当前节次时间；各显示或平台 adapter 继续保留自身需要的格式与降级行为。

在现有纯逻辑 seam 集中选择和解析规则，以小 interface 获得实际 depth。locality 集中在课程钟点语义，leverage 覆盖现有四类调用方；周视图仍按节次定位，左轴仍表示全局节次时刻。

## User Stories

1. 作为学生，我希望课程自带钟点与节次时间不同时，今日课程和详情使用相同的钟点来源，以便知道实际应何时上课。
2. 作为学生，我希望从周视图打开详情也遵守同一规则，以便入口不同不会改变课程时间。
3. 作为学生，我希望从搜索打开详情遵守同一规则，以便搜索结果不会给出另一套钟点。
4. 作为学生，我希望课前提醒按课程显式开始钟点安排，以便提醒与课程显示一致。
5. 作为学生，我希望桌面小组件优先显示课程显式钟点，以便在桌面就能确认上课时间。
6. 作为学生，我希望没有显式钟点的课程使用当前节次时间，以便节次设置能为课程提供钟点。
7. 作为学生，我希望只设置开始钟点时仍保留该值，并从节次表取得结束钟点，以便不丢失已有信息。
8. 作为学生，我希望只设置结束钟点时也逐端处理，以便两个端点遵守同一优先级。
9. 作为学生，我希望节次顺延后只有依赖节次表的端点发生变化，以便明确保存的课程钟点保持稳定。
10. 作为学生，我希望此前教务导入保存的显式钟点继续保留，以便这次整理不会悄悄改动历史课程。
11. 作为学生，我希望缺少可用钟点时仍能看到节次等既有信息，以便继续识别课程。
12. 作为学生，我希望无法得到开始钟点的课程不产生臆造的提醒，以便避免错误通知。
13. 作为学生，我希望今日状态继续按既有起止钟点规则判断，以便进行中和已结束的含义保持一致。
14. 作为学生，我希望周视图左轴继续显示全局节次时间，以便按节次浏览课程。
15. 作为学生，我希望详情、小组件和提醒保留适合各自入口的文字格式，以便界面仍然易读。
16. 作为维护者，我希望同一组课程与节次输入可以覆盖全部调用方，以便修改一次钟点规则就能验证所有相关结果。

## Implementation Decisions

- 在现有纯逻辑与显示/平台调用之间的 seam 集中课程钟点选择和解析；沿用现有 Course 与 SectionTime 领域表示。
- 开始端与结束端独立遵循“显式值优先，仅 null 回退节次表”。不要要求显式两端齐全后才使用它们，也不把空字符串或无法解析的显式值自动当作 null。
- 保持既有空值与解析语义，不顺便清理历史数据、trim 文本、增加严格小时分钟校验或改变日期归一化行为。
- 提醒只依赖可解析的开始端，不因为结束端缺失而取消原本可安排的提醒。
- 今日状态继续在需要的起止端不可解析时使用现有降级规则；详情与小组件保留各自的括号、范围或节次格式。
- 修正详情忽略显式钟点的差异；小组件按共同来源规则读取当前节次回退结果。只统一来源和解析，不强迫所有 adapter 使用同一段最终文字。
- 课程显式钟点包含教务导入时保存的节次快照。全局节次变化后这些已保存值仍优先；仅 null 端使用新的节次时间。
- 不根据钟点是否恰好等于旧节次时间推测来源，不清空、迁移或重写现有课程，也不改变课程编辑保存语义。
- 周视图卡片仍按星期和节次定位；左轴保留全局节次刻度，搜索摘要和周卡片无需新增钟点展示。
- 继续使用现有平台 adapter 验证提醒触发时刻与小组件 payload，不引入只有一个实现的抽象 adapter 或通用日历框架。
- 保证给定相同课程与节次输入时规则一致，不增加打开弹层后的动态订阅、分钟计时器或实时刷新承诺。
- 无须修改数据库或导入格式。

## Testing Decisions

- 用户已确认沿用现有公开 interface 和高位 seam 验收。断言显示文本、今日状态、提醒触发时刻与实际小组件 payload，不断言私有解析函数或内部调用次数。
- 延续现有节次设置到周视图、详情与提醒的流程测试，补充显式钟点与节次钟点冲突的对照课程。
- 核心样例为课程第 1–2 节、自带 08:30–09:00、节次表 08:00–09:40；各入口应使用同一来源语义，格式可各自不同。
- 覆盖只有开始端显式、只有结束端显式、两端均为 null，以及显式空字符串或不可解析字符串的既有降级语义。
- 对全局节次顺延、模板切换和重置，分别验证无显式端随节次变化、WebView 式已保存显式快照保持原值。
- 保留现有今日课程纯计算和提醒计算中显式钟点优先的测试；用提醒触发时刻验证只需要开始端的规则。
- 在现有详情公开入口补充钟点断言，并从周视图、今日课程和搜索复用的详情 seam 验证入口一致。
- 通过已有平台 MethodChannel adapter 捕获小组件 payload，验证显式值和节次回退；不以应用启动测试代替 payload 验证。
- 保留周视图翻页、纵向滚动、节次刻度和无障碍回归，防止钟点集中影响既有布局。
- 实施后运行严格静态分析和全套 Flutter 测试；未做 Android 真机通知或桌面验收时需如实记录。

## Out of Scope

- 历史显式钟点迁移、导入来源追踪、自动同步所有课程到新作息。
- 无效钟点清洗、严格数值校验、跨午夜课程、时区或完整日历规则重构。
- 调整节次时自动重算课程显式钟点，或更改提醒日期与手动当前周的关系。
- 周视图分页结构改造、搜索新增钟点、弹层实时订阅或按分钟自动切换状态。
- 提醒调度并发策略、小组件刷新批次或新的平台适配框架。
