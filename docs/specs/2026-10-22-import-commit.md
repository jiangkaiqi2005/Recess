# Spec：集中导入提交规则，课程与课程平台完整提交

> 状态：已实施，整体标准轴与规格轴复审通过；仅本地提交，未推送或发布。见[实施与评审记录](../2026-10-22-six-spec-implementation-review.md)。

## Problem Statement

学生确认导入时，文件导入与教务导入分别编排目标学期、已勾选课程、课程标识、合并或替换及数据库写入。维护同一条导入规则需要同时理解两个入口。

JSON 导入先提交课程，再逐个课程名替换课程平台；这些步骤没有覆盖整次导入的共同事务。如果平台写入失败，课程可能已经被替换，学生却没有得到一次完整成功的导入结果。现有仓库测试分别覆盖课程和平台，未穿过整次确认提交。

## Solution

将“一次确认后的导入提交”深化为一个 module，使文件导入和教务导入通过同一 seam 完成提交。module 隐藏跨课程与课程平台的写入顺序和事务范围，两个入口继续保留各自的读取、抓取、预览和确认交互。

学生选定的课程及本次明确提供的课程平台全部成功后才报告成功；任一步失败均保留导入前的数据。统一提交 interface 提高 depth，使原子性与成功判定具有 locality，并给现有多个来源 adapter 带来 leverage。

## User Stories

1. 作为学生，我希望 JSON 导入只提交实际勾选的课程，以便保留我选择的课表范围。
2. 作为学生，我希望 ICS 导入只提交实际勾选的课程，以便排除不需要的日历课程。
3. 作为学生，我希望教务导入同样遵守勾选结果，以便不同入口具有一致的确认语义。
4. 作为学生，我希望取消导入确认后课表保持原样，以便安全返回预览。
5. 作为学生，我希望没有有效选择时不会清空课表，以便避免空选择造成覆盖。
6. 作为学生，我希望合并模式保留已有课程并追加所选课程，以便补充课表。
7. 作为学生，我希望替换模式只替换目标学期的课程，以便保留其他学期。
8. 作为学生，我希望一次导入始终写入同一个目标学期，以便课程和平台不会分散到不同学期。
9. 作为学生，我希望文件解析得到的平台分组只应用于实际导入的课程名，以便未勾选课程的平台不会被更改。
10. 作为学生，我希望文件未产生有效平台分组时继续保留已有平台，以便导入课程后不用重新填写平台。
11. 作为学生，我希望同一学期内同名课程继续共享平台，以便同一门课的多个时段无需重复维护。
12. 作为学生，我希望 JSON 中已有的颜色与钟点继续保留，以便导入结果符合文件内容。
13. 作为学生，我希望 ICS 钟点及教务自动配色、节次钟点补全保持原有规则，以便集中提交不会改变来源特性。
14. 作为学生，我希望平台写入失败时课程也回到导入前状态，以便原课表不会被半次导入替换。
15. 作为学生，我希望只有完整提交后才看到导入成功和正确数量，以便判断是否需要重试。
16. 作为学生，我希望提交失败后能够得到明确错误并保留可处理的预览状态，以便按现有交互重试或返回。
17. 作为维护者，我希望从实际使用的提交 interface 测试全部结果，以便一次规则修正覆盖文件和教务入口。

## Implementation Decisions

- 共享的是导入提交规则，不是学校抓取算法，也不是三种来源的完整解析流程。
- 集中所选课程、目标学期、导入模式和平台分组这一份提交输入；执行期间使用一致的输入快照，不在不同阶段重新决定目标或模式。
- 复用现有课程与课程平台持久化能力，将一次导入涉及的课程变更和平台变更放入同一事务。
- 合并与替换继续维持当前语义；替换不主动删除已有课程平台，其他学期保持不变。
- 只将现有解析结果中、对应实际导入课程名的平台分组整体覆盖到目标学期。没有产生分组时保留已有平台，包括文件缺少分组、空列表或全部平台条目无效的情况；不新增空列表清空或逐条合并语义。
- 课程平台继续遵守 ADR-0001 的“学期＋课程名”归属。
- 保留各来源已有的标识生成、显式颜色、钟点来源、教务自动配色与节次钟点补全；不要通过新增大量开关的 interface 硬套来源差异。
- 课程与平台全部提交后才更新成功状态与统计；异常使整次持久化回滚，并由已有导入交互反馈失败。
- 未选择有效课程或取消确认时不进入替换写库。
- 持续使用现有数据库变化与应用级监听刷新课表、提醒和小组件，不在每个导入入口重复触发派生更新。
- 不修改 schema，不新增通用仓储抽象或全局事件机制；只增加实现这次完整提交所需的职责集中。

## Testing Decisions

- 用户已确认沿用现有公开 interface 和高位 seam 验收。主要断言提交后的数据库、导入状态及成功数量，不断言内部函数或调用次数。
- 沿用真实内存数据库 adapter，保留现有课程仓库对替换、追加和学期隔离的测试先例。
- 在两个实际入口使用的共同提交 seam 验证 JSON、ICS、教务已解析结果；来源解析各自已有的测试继续保留。
- 组合覆盖合并和替换、部分勾选、无选择、其他学期同名课程、有效平台分组、未提供平台与多个平台组；明确验证空列表或全部无效条目未产生分组时仍保留已有平台。
- 使用数据库触发器令课程写入后的平台写入失败，断言整次课程、平台和其他学期数据与提交前一致，且不显示成功。
- 覆盖失败后重试，不把上一次未提交的数据留下；不为重试引入新的自动去重语义。
- 保留 JSON 显式颜色和时间、ICS 时间、教务配色及节次时间补全的外部结果断言。
- 以现有课程保存与平台同事务的行为测试为回滚先例，测试真实数据库行为而非模拟调用链。
- 实施后运行严格静态分析和全套 Flutter 测试；真实学校页面登录与抓取可用性单独记录，不由提交测试代替。

## Out of Scope

- 新增学校、来源或文件格式，统一学校抓取脚本，改变登录或横竖屏流程。
- 导入自动去重、冲突自动解决、跨学期移动和后台自动重试。
- 统一所有来源的数据清理规则，新增节次上限、周次裁剪或空白名称规范化。
- 改变课程平台归属、调整预览 UI 或重构整个数据层。
- 把课程钟点读取规则的集中或历史钟点迁移绑定为本次前置工作。
