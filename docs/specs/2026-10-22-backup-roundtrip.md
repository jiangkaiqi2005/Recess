# Spec：备份文件往返正确，恢复失败完整回滚

> 状态：本地草稿，尚未实施；不发布 GitHub。

## Problem Statement

学生把课表导出成备份，再恢复同一份文件时，中文学期名、课程名、教师、地点、备注和课程平台可能变成乱码。文件仍然是合法 JSON，因此恢复可能显示成功，同时写入损坏的文字。

另一个问题发生在恢复的最后阶段：全部学期、课程和课程平台已经替换，激活学期更新却失败，界面报告恢复失败，但旧数据已经消失。这违反了现有备份 module 对失败后保留原数据的承诺。

## Solution

深化现有备份往返 module，让同一个 module 负责备份内容的 UTF-8 字节转换、格式校验和完整恢复结果。文件选择、临时文件与系统分享继续使用现有平台 adapter；页面负责让学生选择文件、查看覆盖确认和获知结果。

恢复时，学期、课程、课程平台及激活状态作为一次提交：全部成功后才报告成功；任一步失败则保留恢复前的数据。将这些规则收进现有 interface 后，提高 depth，使编码和提交规则具有 locality，并给导出与恢复入口带来 leverage。

## User Stories

1. 作为学生，我希望自己导出的中文学期名能够正确恢复，以便继续辨认原来的学期。
2. 作为学生，我希望中文课程名、教师和教室在备份往返后保持原有含义，以便直接使用恢复后的课表。
3. 作为学生，我希望课程备注中的中文、英文和 emoji 不会损坏，以便保存完整的学习提示。
4. 作为学生，我希望课程平台的用途、平台名和链接正确恢复，以便继续访问对应课程使用的平台。
5. 作为学生，我希望多个学期及其课程一起恢复，以便换设备后保留完整的课表。
6. 作为学生，我希望恢复后仍进入备份所标记的激活学期，以便马上看到需要的课程。
7. 作为学生，我希望没有激活标记的有效旧备份继续按既有规则选定学期，以便使用历史备份。
8. 作为学生，我希望应用继续读取原有 Hormone 标记的兼容备份，以便已有文件仍然可用。
9. 作为学生，我希望无效文件在覆盖前被拒绝，以便现有课表不受损坏。
10. 作为学生，我希望取消文件选择或覆盖确认后不发生写入，以便安全地退出恢复流程。
11. 作为学生，我希望恢复任一阶段失败时仍保有原来的学期、课程和平台，以便继续使用原有数据。
12. 作为学生，我希望恢复激活状态失败也能回滚全部替换，以便“恢复失败”不会意味着原课表已丢失。
13. 作为学生，我希望只有完整恢复后才看到成功统计，以便相信界面报告的结果。
14. 作为学生，我希望成功恢复后学期列表和课表显示新数据，以便不用重启应用。
15. 作为维护者，我希望通过实际文件字节与现有恢复入口验收，以便覆盖字符串仓库测试漏掉的编码问题。
16. 作为维护者，我希望保留原有备份格式和课程平台归属，以便这次修复不要求用户迁移数据。

## Implementation Decisions

- 深化现有备份 module，补齐它遗漏的编码与完整提交职责；不再新增只转发调用的 shallow module。
- 导出和恢复共享 UTF-8 语义。恢复遇到无效 UTF-8 时在写库前明确拒绝，避免带替换字符继续覆盖数据。
- 备份校验继续发生在覆盖确认之前；确认的内容与实际恢复的内容应一致。
- 将数据替换和最终激活学期选择放入同一个数据库事务，覆盖所有学期、课程和课程平台写入。
- 任一写入失败均保持恢复前的数据与激活状态，不把部分完成当作成功。
- 保留现有备份格式、旧应用标记兼容、无激活标记时选第一个学期，以及既有字段归一化语义。
- 课程平台继续按“学期＋课程名”归属，遵守 ADR-0001；不改为挂在单条课程上。
- 文件选择、文件落地和系统分享保留现有平台 adapter；备份内容的编码与提交规则位于这些 adapter 之后的既有 seam。
- 恢复成功后的必要 Provider 刷新集中在恢复操作的应用入口，页面无需记住多项缓存清单；继续由现有应用级监听触发小组件和提醒更新。
- 成功统计只描述已经完整提交的数据；错误通过当前恢复交互反馈，不新增重试队列或后台任务。
- 不要求数据库 schema 或备份版本升级。

## Testing Decisions

- 用户已确认沿用现有公开 interface 和高位 seam 验收；测试应断言最终数据、激活状态、界面反馈和实际文件内容，不断言私有函数、内部拆分或调用次数。
- 沿用现有备份仓库的真实内存数据库 adapter，覆盖多学期、课程、平台、颜色、钟点、周次与激活状态。
- 增加一次真实 UTF-8 文件字节往返，使用中文、英文和 emoji 样例；穿过恢复入口的字节读取 seam，不能只把 String 直接传入仓库。
- 对无效 UTF-8、无效 JSON、错误应用标记及既有格式校验失败，断言覆盖前拒绝且数据库不变。
- 用真实数据库触发器令最终激活写入失败，断言旧学期、旧课程、旧平台和激活标记整体保留；另增加数据插入失败的回滚覆盖。
- 以现有备份仓库测试为格式兼容先例，以设置到课表的流程测试为刷新先例；保留旧格式与无课程平台字段的回归。
- 验证取消选择和取消确认不写库，成功后列表与课表可见新数据。
- 实施后运行严格静态分析和全套 Flutter 测试；平台分享与原生显示是否做过真机验收需单独记录。

## Out of Scope

- 把主题、提醒、节次设置或其他新数据加入备份格式。
- 云备份、远程同步、加密备份、文件版本管理和自动恢复。
- 修改既有字段清理规则，或从已经乱码的历史数据推测恢复原文。
- 引入通用文件框架、通用仓储抽象或全局事件总线。
- 导出期间并发编辑的一致性快照优化；本次没有将该静态风险列为已复现故障。
