# 冷暖平衡课程配色（20% 柔化）

## 问题与已确认决定

当前十色课程块的大面积色相搭配不协调，用户希望降低刺激感。在同一份课表原型中，用户先确认 20% 柔化，再明确选择“冷暖平衡”，并要求使用 implement-and-codereview 工作流落实。

本规格将用户已选原型作为视觉基准，覆盖 AGENTS.md 中旧默认蓝色与十色色板的描述；其他仓库约定仍然适用。

## 用户故事

- 作为使用已有课表的人，我更新后就能看到协调的新配色，无需重新导入。
- 作为新增或编辑课程的人，我能选择与课表一致的八种课程颜色。
- 作为使用备份或自定义 JSON 颜色的人，我的原始数据与自定义颜色不被无关改写。

## 冻结色值与显示行为

源自已确认的本地原型 `.claude/prototypes/course-colors/palettes.json` 的 `schemes.balanced.levels[20]`。这些是最终显示值，不应在运行时再次柔化、压暗或重新生成。

| 顺序 | 色系 | 浅色 ARGB | 深色 ARGB |
| --- | --- | --- | --- |
| 0 | 蓝 | 0xFF4399F1 | 0xFF217BD1 |
| 1 | 青绿 | 0xFF4BA89A | 0xFF298B7E |
| 2 | 暖橙 | 0xFFE3753F | 0xFFC3581D |
| 3 | 靛紫 | 0xFF7C83E7 | 0xFF6266C7 |
| 4 | 莓红 | 0xFFE36679 | 0xFFC2485D |
| 5 | 青蓝 | 0xFF46A4C1 | 0xFF2287A3 |
| 6 | 暖棕 | 0xFFB28C6D | 0xFF947052 |
| 7 | 玉绿 | 0xFF53A88D | 0xFF348B72 |

- 新建默认色为索引 0 的浅色色值；自动配色按八色顺序循环。
- 浅色色值作为持久化色板标识，切换主题只改变显示，不改数据库记录。
- 课表卡片保留原型中的白色课名与 90% 不透明度的白色教室、实色圆角、字号和语义信息。
- 不修改全局主题、排版、卡片尺寸、路由、切周动画或滚动行为。
- 已知限制：浅色板纯白课名的最小 WCAG 2 对比度约 2.851:1，深色约 4.127:1；90% 白色教室的实际对比度更低。用户在看到白字方案与可读性说明后选择该原型。本次以冻结配色与白字为准，不暗改为深字、压暗底色或宣称达到 AA。自定义颜色的已有白字可读性处理保留。

## 旧色与自定义颜色

原十色顺序为：`5B8DEF, 3FBFA8, F2A25C, 9B8AFB, EF6E8D, 4FA3E3, E8BE50, 63C98D, C08CE8, F08C7C`（均为不透明 ARGB）。

- 原十色的索引 i 显示为新色板 i % 8，对齐原型对原课程的分配方式；第 8、9 种旧色分别映射新蓝、青绿。
- 映射仅用于显示与编辑色板的选中识别，不做数据库迁移或批量重写。编辑旧课程但未主动改色时，保存不得偷偷重写原颜色。
- 原色板以外的自定义 ARGB 保留；现有 JSON 解析、备份导出与恢复仍按原始值读写，不强制套用八色。
- 周视图使用精确的主题色值；课程编辑页的色样、选中态，搜索结果与详情色标使用同一套显示规则，旧色和新色都能正确识别。
- 桌面小组件的现有课程颜色字段按新浅色板解析已知旧色；不改变其原生布局、主题机制或异常处理。

## 实施边界与依赖

一个独立工作单元，先冻结色值，再实现共享颜色解析与消费处接入，最后验证与双轴评审。无前置票，无运行时配色依赖，不修改数据库结构和生成代码语义。

沿用当前 `my-version` 分支；初始 HEAD / unitBase 为 `56c85c4425bbfb99d5b6dfa62b0d5e3a2b18b2fb`。工作区原有未追踪 `.agents/` 与被忽略 `.claude/`（技能、原型）属于本地工具，不提交。实施代理仅提交本单元代码、测试、本规格与必要的 DESIGN.md 同步，中文提交标题和非空中文说明，无协作者署名；不推送、开 PR 或发布。

## 验证

1. 精确验证八色的浅/深显示值、默认色与自动配色循环，不以“白字至少 3:1”替代冻结色值验收。
2. 覆盖十种旧色的映射、已是新色时的幂等解析、自定义色保留与主题切换；保护原始备份/JSON 行为。
3. 课程卡片部件覆盖实际最终 Material 颜色、保留白字和无布局变化；编辑页覆盖旧色对应的选中态与主动换色、保存行为（适当复用现有测试）。
4. 新旧配色的搜索/详情色标一致，桌面小组件传值接入同一映射；提供代码证据或聚焦验证。
5. 按仓库约定运行 `dart run build_runner build --delete-conflicting-outputs`、`flutter analyze --fatal-infos --fatal-warnings`、`flutter test`。针对纯配色变更不额外扩展无关测试。
6. 协调者核对最终色值与确认原型，并检查 Android 构建或真实 Flutter 渲染；实机运行若未验证，明确说明。
