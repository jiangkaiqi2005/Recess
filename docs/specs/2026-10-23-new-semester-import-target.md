# Spec：新建学期并导入到新学期，可切回旧学期

> 状态：已实施（2d368df），四张票标准轴与规格轴评审均通过；已推送 develop，正式签名包已覆盖安装到真机并经用户确认可用。

## Problem Statement

学生换学期时想导入新课表，但导入只会写进当前学期。用“替换”会删掉旧学期的全部课程，用“合并”又会让新旧课程混在一起。

应用其实已经能新建学期：学期管理页右下角可以添加，并可在保存后设为当前学期。但这个入口离导入很远，导入页也不告诉学生课程会写进哪个学期；新建弹层的“保存后设为当前学期”默认关闭，忘了打开就会导入进旧学期。

即使学生按对了步骤，切到新学期后也无法再把旧学期设为当前学期，只能靠备份恢复才能回看旧课表。切换当前学期后，课表页的查看周还停在旧学期的周次。

另外，新学期的名称可以留空，开学日期默认是今天，与“开学前建好新学期”的常见用法不符。

## Solution

学生在导入页就能看到“将导入到：<当前学期名>”，旁边有“新建学期”按钮。从这里新建的学期保存后一律成为当前学期，回到导入页即可导入；新学期没有课程，使用“替换”也不会影响旧学期。

学期管理页新建学期时，“保存后设为当前学期”默认打开。非当前学期的编辑弹层提供“设为当前学期”，学生可以随时切回旧学期；课表页、上课提醒和桌面小组件随之切换，不删除任何数据。

当前学期切换后，课表页的查看周跳到新学期的当前周；新学期尚未开学时显示第 1 周。新建学期的开学日期默认下一个周一（今天是周一则为今天），学期名称必填。

## User Stories

1. 作为学生，我希望在导入页看到课程会写进哪个学期，以便导入前确认不会覆盖错的学期。
2. 作为学生，我希望在文件导入页的初始界面看到目标学期，以便选择文件前就能确认。
3. 作为学生，我希望在教务导入的选学校界面看到目标学期，以便登录抓取前就能确认。
4. 作为学生，我希望在导入页直接新建学期，以便不必绕到设置里的学期管理。
5. 作为学生，我希望从导入页新建的学期保存后自动成为当前学期，以便马上把课导进去。
6. 作为学生，我希望从导入页新建学期时不必操作额外开关，以便少一步、不出错。
7. 作为学生，我希望新建完成后回到导入页并看到目标学期已换成新学期，以便确认接下来导入的位置。
8. 作为学生，我希望往新建的空学期“替换”导入时旧学期的课程保持不变，以便保留旧课表。
9. 作为学生，我希望往新学期导入时旧学期的课程平台保持不变，以便切回旧学期时信息完整。
10. 作为学生，我希望登录和预览阶段不出现新建学期入口，以便不会让已经抓取的周次作废。
11. 作为学生，我希望在学期管理页新建学期时“保存后设为当前学期”默认打开，以便新学期建好就生效。
12. 作为学生，我希望在学期管理页仍可关掉这个开关，以便提前建好下学期而不立即切换。
13. 作为学生，我希望非当前学期的编辑弹层里有“设为当前学期”，以便切回旧学期查看课表。
14. 作为学生，我希望当前学期的编辑弹层不显示“设为当前学期”，以便界面不出现无效操作。
15. 作为学生，我希望点“设为当前学期”后弹层关闭、学期列表把它标为当前，以便确认切换成功。
16. 作为学生，我希望切换当前学期不删除任何学期的课程或课程平台，以便来回切换无损。
17. 作为学生，我希望切换当前学期后课表页显示新当前学期的课程，以便看到对应课表。
18. 作为学生，我希望切换当前学期后上课提醒和桌面小组件改用新当前学期，以便提醒与课表一致。
19. 作为学生，我希望切换当前学期后查看周跳到新学期的当前周，以便不停留在旧学期的周次。
20. 作为学生，我希望切到尚未开学的学期时查看周为第 1 周，以便看到开学第一周的课。
21. 作为学生，我希望切到设置了手动当前周的学期时查看周跟随该手动当前周，以便调课或假期设置仍生效。
22. 作为学生，我希望新建学期并设为当前后查看周同样跳到新学期的当前周，以便与手动切换一致。
23. 作为学生，我希望新建学期的开学日期默认是下一个周一，以便开学前建学期时少改一次日期。
24. 作为学生，我希望今天是周一时开学日期默认为今天，以便当天开学时不被推迟一周。
25. 作为学生，我希望新建学期的总周数默认仍为 18，以便沿用常见学期长度。
26. 作为学生，我希望学期名称为空时不能创建，以便学期列表和导入页不出现空白名称。
27. 作为学生，我希望只有空格的名称也视为空，以便不会保存看似空白的学期。
28. 作为学生，我希望编辑已有学期时名称同样必填，以便旧的空名称学期在下次保存时补上名称。
29. 作为学生，我希望新建或切换失败时仍显示失败并保持原当前学期，以便继续使用原课表。
30. 作为维护者，我希望这些行为通过真实内存数据库和真实页面验收，以便不依赖私有实现。

## Implementation Decisions

- 不新增路由。导入页的“新建学期”复用学期管理页现有的新建学期底部弹层，以弹层参数区分“从导入页新建”：此时隐藏“保存后设为当前学期”开关，并始终以设为当前学期的方式保存。
- 目标学期提示与“新建学期”按钮只出现在两个导入起始界面：文件导入页尚未选择文件时的初始界面，以及教务导入的选学校界面。登录、抓取和预览阶段不出现。
- 目标学期提示读取现有当前学期 Provider；新建学期提交后由现有学期变更入口统一失效相关 Provider，提示自动更新。
- 教务导入依赖抓取时的当前学期总周数展开周次，并在提交时核对学期快照；本 Spec 不改这一校验，而是通过只在起始界面提供新建入口来避开它。
- 学期管理页新建弹层中“保存后设为当前学期”的初始值改为打开；编辑已有学期时仍不显示该开关。
- “设为当前学期”只出现在非当前学期的编辑弹层。点击后通过现有学期变更入口完成激活（不保存表单中未提交的其他修改），成功后关闭弹层；失败沿用现有失败提示，原当前学期保持不变。
- 学期变更入口在激活成功后负责让查看周回到新当前学期的当前周，规则与应用启动时一致：优先手动当前周，否则按开学日期推算，并限制在 1 到总周数之间。
- 查看周重置只在当前学期发生变化时触发；保存非当前学期、或保存当前学期但不改变当前学期身份时，不打断学生正在查看的周。
- 新建学期的开学日期默认值为下一个周一（今天是周一则为今天），只用于新建；编辑已有学期保留其原开学日期。应用首启播种默认学期的“最近周一”规则不变。
- 学期名称去除首尾空白后为空时，新建弹层的“创建”和编辑弹层的“保存”不可点击。保存时写入去除首尾空白后的名称。
- 无 schema 变化，无数据迁移，不新增 Provider 层级或仓储方法；激活沿用现有单一激活写入规则。
- 术语沿用 GLOSSARY.md：当前学期、学期、课程、课程平台、当前周、查看周。

## Testing Decisions

- 用户已确认沿用现有 seam：真实内存数据库 + ProviderContainer + pump 真实页面，只断言可见结果和数据库最终内容，不断言调用次数或私有状态。不新增 seam。
- 学期管理页（延续现有学期流程测试）：
  - 新建弹层的“保存后设为当前学期”默认打开，直接创建后新学期为当前学期。
  - 关掉开关创建后原当前学期不变。
  - 新建弹层开学日期默认值在周一与非周一两种“今天”下符合规则；测试需要可控的“今天”，沿用现有测试控制时间的做法。
  - 名称为空或全为空白时“创建”/“保存”不可点击；带首尾空白的名称保存后被去除空白。
  - 非当前学期编辑弹层出现“设为当前学期”，当前学期不出现；点击后列表标记切换、两个学期的课程与课程平台全部保留。
  - 用数据库触发器令激活写入失败，断言显示失败、原当前学期不变（沿用现有故障注入写法）。
- 导入起始页：
  - 文件导入页初始界面与教务导入选学校界面显示“将导入到：<当前学期名>”。
  - 从导入页打开新建弹层时不显示开关；创建后提示换成新学期名称。
  - 从导入页新建后进行一次“替换”导入，断言课程只写入新学期，旧学期的课程与课程平台不变（可在文件导入路径上完成，复用现有导入提交测试的数据构造）。
- 课表页查看周（延续现有当前周流程测试）：
  - 切换到已开学学期后查看周等于其推算当前周；切到未开学学期为第 1 周；切到有手动当前周的学期跟随手动当前周。
  - 学生手动翻到其他周后再保存非当前学期，查看周不变。
- 实施后运行代码生成、`flutter analyze --fatal-infos --fatal-warnings` 与全套 `flutter test`。

## Out of Scope

- 节次时间按学期区分；节次时间继续由所有学期共用。
- 修改“替换 / 合并”导入逻辑、导入预览、冲突检测或教务抓取后的学期快照校验。
- 在登录、抓取或预览阶段新建或切换学期。
- 在导入页内联填写新学期表单，或让导入在提交时才决定目标学期。
- 跨学期复制或移动课程、按学期导出、学期归档或回收站。
- 修改应用首启播种默认学期的规则，或允许没有当前学期的状态。
- 课表页直接切换学期的入口（例如顶栏学期选择器）。
